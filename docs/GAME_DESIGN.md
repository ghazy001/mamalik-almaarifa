# Game design

An original fantasy knowledge-and-conquest game for three Arabic-speaking players. The intended loop is: choose a neighboring target, answer a question, resolve ownership, plan the next move. Knowledge determines outcomes; map position determines available choices. Modern Standard Arabic is the default, with future locale dictionaries anticipated but no premature French/English release.

The MVP aims for 10–15-minute matches; M1's 36 turns and timers are provisional and have not been playtested. A correct answer wins a neutral territory. Occupied targets create a shared-question duel. Capturing an original home castle eliminates its owner and transfers their lands. Castle control and a bounded turn limit ensure completion; joint score ties avoid arbitrary seat-based winners. See GAME_RULES for exact precedence.

## Experience foundation

Ink/navy surfaces, teal/sapphire faction accents, restrained gold, locally bundled Noto Sans Arabic, and original geometric heraldry establish the direction. There is no borrowed game branding or artwork. The shell explains the loop and links to `/play` for a local match, `/online` for guest matchmaking/invitations and `/map` for a paused exploration preview. It distinguishes scripted opponents from real guest seats and explains that accounts/results persistence are unavailable.

The first M2 map is **أرخبيل المنار**: original raised isometric islands, procedural trees/hills, three faction castle silhouettes, depth sorted layers and visible routes matching the canonical graph. This visual archipelago changes no rules or move costs. Arabic territory names and numbered DOM controls provide meaning independent of canvas precision and color. Only the active castle's two legal neighbors are selectable in this initial snapshot. Selection draws a bright route and outline; it never awards territory. No ambient animation or audio is enabled in this slice, including for reduced-motion users. The initial preview has no battles; `/play` and `/online` now add capture/defense effects. Full scenes, zoom/pan and measured mobile performance remain polish work.

`tokens.css` owns colors/radius; Tailwind and a customized shadcn-style Button own reusable interaction styles. Native RTL, logical margins/borders, isolated LTR identifiers, visible focus and a skip link form the accessibility baseline. Decorative heraldry is hidden from assistive technology; critical information is real DOM text. Motion respects reduced-motion preferences. Noto Sans Arabic is supplied by the `@fontsource` package with its bundled open-font license. Radix/shadcn patterns are MIT licensed.

## Milestone boundaries

The M2 `/play` experience now connects that same map to a complete local match: one human and two explicitly scripted opponents, timed four-choice questions for attack/defense, answer locking, result reveal with source notes, captured ownership/flags, score updates, castle elimination and a results/replay screen. A native dialog can be minimized without pausing time. Human result review waits for Continue; observer/bot turns progress quickly. Short capture/defense effects respect reduced motion. The fixture questions are original development content with source notes/calculation checks, not an editorially approved release bank. This is inspectable browser simulation; M3 server authority is isolated in the separate online flow; M4 identity and content tooling are separate from this offline experience.

M1 tests the rules without a renderer. M2 adds a complete offline match with original Phaser isometric terrain, accessible DOM targets and question overlays. Its bots remain explicitly scripted. M3 introduces actual room coordination and timers. Reviewed sourced questions and identity/persistence belong to M4. Audio and the full art pass belong to M5.

No power-up economy, pay-to-win mechanics, live generated questions, public chat or deferred social systems are included. Cosmetic polish must never hide uncertain rules or create a misleading multiplayer claim.

The first M3 slice adds `/online`: private invitation rooms for three real guests with readiness, authoritative timers, attack/defense and shared results. Local bots remain confined to `/play`. The next M3 slice adds explicit guest matchmaking with real seat counts and cancellation. Once three arrive, each confirms readiness within 60 seconds. No bots fill a missing seat; an expired preparation cancels without a winner. Accounts, durable history and release content remain deferred.

M3 now meets the documented local guest-match completion contract: three real browser sessions finish under simulated latency and in-question recovery/suspended-tab scenarios. Connection guidance and manual restore stay inside the accessible native dialog; reconnect never pauses or resets a battle. This validates the bounded prototype, not competitive fairness or production hosting. See M3_RESILIENCE.md.

M4 includes local sourced-question storage, a Supabase-authenticated content API and an Arabic editorial workspace: immutable revisions, explicit review/publication, transactional audit, project-scoped account roles and safe retries. Imported fixtures remain drafts until reviewed. Trusted operator CLI labels do not authenticate reviewers; HTTP authors/reviewers derive from verified accounts. `/signin` serves existing content-team accounts; `/admin` exposes only authorized editorial workflows. Online rooms default to public fixtures and can explicitly use a private snapshot of published database revisions. New rooms reject insufficient content; existing rooms keep their initial revision set. Hosted identity verification, player accounts, an editorially reviewed release bank and durable results remain. See M4_PUBLISHED_ROOM_BANK.md and ADRs 0007–0010.
